# The Readograph phone app

The app lives in `mobile/`, an npm workspace next to the website. It is an Expo SDK 58 app
(React Native 0.88, the new architecture, Reanimated 4) with Expo Router. Its catalogue, filter,
sort and sharing logic comes from `@readograph/core` (`packages/core`), the same code the website
runs. The plan is `docs/mobile-app-plan.md`; this file describes what is built.

Status: PRs 4 and 5 of the plan. Films, Events and Radar work; My films and Account are
placeholders. The device checks are still open (see "Device checks").

## Setup

```sh
npm install                # at the repository root; installs the website and the app
cd mobile
npx expo start             # Metro, for a development build or Expo Go
npx expo-doctor            # dependency and config checks
npx expo export --platform ios --output-dir dist/ios          # bundling smoke test
npx expo export --platform android --output-dir dist/android
```

The root `npm run typecheck` includes `tsc -p mobile`, `npm run lint` lints `mobile/`, and
`npm test` runs the app's Vitest suites (`mobile/src/**/*.test.ts`). `ios/` and `android/` are
generated by continuous native generation and are not committed.

The root `package.json` pins `react` and `react-dom` to the version React Native 0.88 needs
(`overrides`, 19.3.0): without it npm hoists a newer React for a `*` peer range and the app would
load two copies. The website uses Preact and installs no React of its own.

Pinned versions (`mobile/package.json`):

| Package                        | Version |
| ------------------------------ | ------- |
| expo                           | 58.0.23 |
| expo-router                    | 58.0.30 |
| react-native                   | 0.88.1  |
| react, react-dom               | 19.3.0  |
| react-native-reanimated        | 4.7.1   |
| react-native-worklets          | 0.13.0  |
| react-native-screens           | 4.30.1  |
| react-native-safe-area-context | 5.11.1  |
| @shopify/flash-list            | 2.3.2   |

To move to a later SDK, run `npx expo install expo@^<n>` and `npx expo install --fix` in
`mobile/`, set the two `overrides` to the React version the new React Native needs, and run
`npm install` at the root. If `npm ls react-native` then shows two copies, the lockfile kept the
old tree: remove the app's packages from it and resolve them again.

## Running it on a phone

There is no Xcode and no Android SDK on the development Mac, so the app has only been bundled
there, not launched. Two ways to run it:

1. **Expo Go from the App Store or Google Play.** The store Expo Go supports SDK 58 only, which
   is the SDK this app uses. Run `npx expo start` in `mobile/` (add `--port 8083` if another
   program holds 8081) and scan the QR code with the phone on the same network. Limits of
   Expo Go:
   - The embedded fonts are absent, because config plugins do not run there. Text falls back to
     the system font, so League Spartan cannot be checked in Expo Go.
   - The app's own icon, name and Android package are Expo Go's.
2. **A development or preview build through EAS.** EAS profiles arrive with PR 7; until then
   `npx eas-cli@latest build --profile development` needs `expo-dev-client` and an `eas.json`,
   which are not in the repository. A build embeds League Spartan through the `expo-font` config
   plugin and the native modules listed in `mobile/package.json`.

Starting Expo must leave the working tree clean. Expo CLI maintains `include` in
`mobile/tsconfig.json`; the committed list is the one SDK 58 writes (no `expo-env.d.ts`, because
typed routes are off).

## Catalogue loading (plan section B)

`mobile/src/catalogue/` implements the loading rules; the pure part is tested under Vitest.

| File           | Role                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| `loader.ts`    | Fetches `${SITE_ORIGIN}/catalogue.json` and the files it names; rules 2, 4 and 5 |
| `cache.ts`     | One JSON file per generation; reads the newest that passes the checks            |
| `files.ts`     | The cache folder on the device (`expo-file-system`, the app's cache directory)   |
| `store.ts`     | What screens read; rule 1 at launch, rule 3 on returning to the foreground       |
| `provider.tsx` | Wires the store to React and to `AppState`                                       |

- A missing data file is any 404, any `text/html` response and any body that is not JSON.
  Cloudflare Pages serves the site in SPA mode, so a missing `/data/*` file returns 200 with the
  index page. The loader then reads the manifest once more and retries.
- The cache is written as a new file per `generatedAt`, then older files are deleted. An
  interrupted write leaves a file that fails to parse, and the previous one is used.
- `ACCEPTED_SCHEMAS` in `loader.ts` lists the schema versions the app reads. After a breaking
  bump of `DATA_SCHEMA_VERSION`, keep the previous version there for 30 days (`AGENTS.md`).
- A newer schema keeps the cached catalogue on screen with a banner asking for an app update.

## Navigation

- `app/(tabs)/_layout.tsx` renders the five tabs: Films, Events, Radar, My films, Account.
  Each tab folder has its own native stack, so the film detail is pushed inside its tab.
- Films, Events and Radar share `src/navigation/list-stack.tsx`: the list, the film detail
  (`[id].tsx`; Events and Radar re-export the Films screen) and the Filters sheet
  (`filters.tsx`). Each of the three tabs has its own `ViewState` store
  (`src/films/view-context.tsx`); the stack layout picks it with `ViewScope`, so the list, the
  detail and the sheet of a tab read and write the same state.
- **Tabs fallback.** Native tabs are stable since SDK 58 and are imported from
  `expo-router/native-tabs` (the `unstable-native-tabs` path is deprecated). The fallback is
  kept until the device checks pass: set `USE_NATIVE_TABS = false` in
  `mobile/src/navigation/tabs.ts` and the same route files render in Expo Router's JavaScript
  `Tabs`, with the same labels and symbols. Nothing else changes. Once native tabs pass on both
  platforms, the switch and `javascript-tabs.tsx` can be removed.
- Headers are the native stack's, in the masthead red, with the wordmark as the Films title.
  Expo Router 58 changes the default on iOS 26 and later to a transparent header with the
  content drawn underneath and the system's fonts. `app/_layout.tsx` calls
  `enableLegacyHeaderAppearance()` to keep the opaque red header of the approved design. Expo
  marks that function deprecated and plans to remove it, so the header needs a redesign for the
  system appearance before a later SDK; Android headers are unaffected.

## Discovery (PR 5)

- **Filters sheet.** A `formSheet` route per list tab, configured as the plan says:
  `sheetAllowedDetents: [1]`, `sheetGrabberVisible: true`, `sheetCornerRadius: 12`, the
  scroll-to-edge expansion left at its default (the options are unchanged in
  react-native-screens 4.30). `@gorhom/bottom-sheet` is not used: nothing found in SDK 58
  shows the Android form sheet failing the checks, and they need a phone. If the
  device checks fail on Android, the plan's fallback (a `BottomSheetModal`) replaces the route's
  presentation only; `src/filters/filters-sheet.tsx` is the content either way.
- The sheet owns no state. Every change writes straight to the tab's store, so the list behind
  updates live. Top to bottom: the quick filters from core's `shortcutItems` in capitals (MY
  WATCHLIST and MY CINEMAS are hidden until PR 6 adds accounts, exactly as `shortcutItems`
  hides them for a signed-out reader without saved cinemas; NEAR ME opens Near me), search,
  When (day, time), Where (cinema with the independent toggle, borough, membership), What
  (genre, format, language, year by decade, accessibility), Only show (sold out, under two
  hours), and a footer bar with Reset all and Show N films.
- Differences from the website's sheet: the year row offers decades only, the time row has no
  From and Until fields (no time picker dependency; a time range set elsewhere still shows and
  clears as a chip), and the day row is a list rather than the website's calendar.
- **Active-filter chips** (`src/films/chips.ts`) list one chip per choice and end with Clear
  all, which keeps the search text and the sort. The Filters button's badge uses the website's
  count.
- **Near me** runs inside the sheet: foreground permission (explained before the system
  prompt), one position at balanced accuracy, the cinemas within 1 to 10 miles through core's
  `nearbyVenues` (which tests each distance with `withinRadius`). Refused for good, it explains
  and offers Settings. Applying it sets a temporary cinema filter, as on the website.
- **List ⇄ Posters.** The choice is stored in AsyncStorage as `london-cine.film-view.v1`
  ("list" or "posters") and offered only where core's `supportsPosters` is true. The morph is a
  FLIP overlay (`src/films/use-morph.ts`, maths in `morph.ts`): it reads the visible cells from
  FlashList's own layouts (`getLayout`) instead of a native `measure`, hides the cells, switches
  `numColumns` (FlashList 2 swaps its layout manager without remounting), restores the anchor
  film's offset, then flies every visible poster from one shared progress value with the plan's
  timings. A second tap reverses it; poster taps wait until it settles.
- **Switches**, one constant each in `src/ui/motion.ts`:
  - `MORPH_STYLE = "flip"`. Set `"crossFade"` for the plan's fallback, a 160 ms fade with the
    scroll anchor kept. Reduced motion always uses a 120 ms fade.
  - `IOS_POSTER_TRANSITION = "zoom"`: Expo Router's `Link.AppleZoom` and
    `Link.AppleZoomTarget` (iOS 18 and later; earlier iOS gets the push by itself, because the
    component falls back to a plain wrapper). `"push"` turns it off.
  - `ANDROID_POSTER_TRANSITION = "fade"`: the container transform needs Reanimated's
    shared-element transitions, which 4.7.1 still keeps behind the experimental static flag
    `ENABLE_SHARED_ELEMENT_TRANSITIONS` (default false), and Expo Router 58 adds no Android
    equivalent of the zoom. Android therefore uses the plan's fallback: the
    standard push with the detail poster fading in over 160 ms. `"push"` turns the fade off.
- **Events** groups by London date with the website's two views and event types; **Radar**
  shows one section at a time (few screenings soon, 35mm and 70mm, IMAX) with the website's line
  explaining why each film is listed. The Release calendar and Retrospectives keep the
  website's group headings in the list and the grid.

## Theme and motion

- `mobile/src/ui/tokens.ts` transcribes the website's dark Picturehouse colours and the
  `--text-1` to `--text-9` scale (13 to 42 points, body 16). Screens use no other colours or
  font sizes. The app is dark only (`userInterfaceStyle: "dark"`); a light set would be a second
  palette in the same file.
- `mobile/src/ui/motion.ts` holds the easing (`Easing.bezier(0.2, 0.8, 0.2, 1)`) and the
  transition switches; the durations live in `motion-values.ts` so the morph maths can be
  unit-tested without React Native.
- **Fonts.** League Spartan (SIL Open Font License) is embedded from the upstream TTFs
  (`mobile/assets/fonts/SOURCE.txt`). Clash Display is not embedded: Fontshare's licence, as
  recorded in `public/fonts/fontshare/SOURCE.txt`, covers self-hosting on the website and not
  redistributing the font files, and an app binary and this public repository would both
  redistribute them. The wordmark is therefore `mobile/assets/images/wordmark.png`, a 3×
  screenshot of the website's masthead at 390 points (rendered with Playwright from
  `npm run preview` with fixture data). Re-render it the same way if the masthead changes.

## Device checks

Every check below needs a real phone; none has been done. PR 0's spike (plan section "PR 0")
could not run on this machine, so its eight items are folded in here.

1. Core on Hermes: accent folding in search, numeric title sorting and Europe/London dates match
   the Vitest results on iPhone and Android.
2. Native tabs and native stacks on both platforms; otherwise switch to the JavaScript tabs.
3. FlashList scrolls about 1,500 films without dropped frames on a mid-range Android phone;
   the films file downloads in under three seconds on mobile data.
4. An EAS preview build installs on dio's phone.
5. League Spartan renders on both platforms; the wordmark image is sharp in the header.
6. The Filters drawer's eight checks (PR 5).
7. The List ⇄ Posters morph (PR 5).
8. The iOS zoom transition and the Android poster fade that stands in for the container
   transform (PR 5).

PR 4's and PR 5's own device checks are listed in their pull requests.
